# AGENTS.md — working on Solum

Instructions for coding agents (FlutterFlow agent, Claude Code, others).
Brand rules are in `CLAUDE.md` and `.claude/skills/solum-brand/`; follow them.

## What to build from

1. `docs/design/SPEC.md` — the v2 design spec. Final for v1 except items marked *placeholder*.
2. `docs/design/screens/*.png` — reference captures (scaled; take sizes from the spec, not pixels).
3. `docs/design/prototype/Solum App v2.dc.html` — the clickable prototype. Its logic
   class (bottom of the file) is the behavioral source of truth; `lib/state/solum_store.dart`
   ports it method by method.
4. `docs/design/chat-*.md` — the design conversations (why decisions were made).

## Two targets

- **Flutter code (`lib/`)** — the full app. Edit here when working in code.
- **FlutterFlow (`flutterflow/`)** — theme values, data schema, custom widgets,
  actions and functions to paste into a FlutterFlow project, plus page-by-page
  build instructions and agent prompts (`flutterflow/README.md`).
  FlutterFlow cannot import `lib/`; it pushes its own code to a separate branch.

## Conventions

- Never hard-code a color in a screen; use `context.cs`, `context.sc` (SolumColors),
  `context.mc` (map colors) or `SolumPalette` for the few fixed brand values.
- New behavior goes in `SolumStore` first (with a test in `test/store_test.dart`),
  then the widget reads it. Widgets stay thin.
- Copy strings come from the spec verbatim. Sentence case, verbs first, numbers
  before nouns, no exclamation marks.
- Every new screen state gets a start-state name in `SolumStore.startStates` /
  `applyStart` so it can be opened directly (`?start=` on web).
- Integrations (Apple/Google sign-in, RevenueCat, geolocator, a real geocoder,
  persistence) replace the demo classes behind the existing interfaces.

## Commands

```bash
flutter pub get
flutter analyze          # must be clean
flutter test             # 26 tests
flutter run --dart-define=SOLUM_START=map
# Web preview of any state:
flutter create --platforms web .   # once, not committed
flutter build web --no-web-resources-cdn && python3 -m http.server -d build/web 8080
# open http://localhost:8080/?start=map-log  (add &dark=1 for dark mode)
```

Start states: welcome, how, location, signup, paywall, tour, map, map-log,
map-log-retry, map-follow, map-pin, map-add, manual-add, map-search,
map-directions, outline, outline-name, area-almost, area-complete,
limit-contacts, limit-area, followups, contacts, contact, contact-edit, settings.

## Known gaps (next steps)

- Map tiles are OpenStreetMap raster tiles tinted toward the Solum palette.
  For the exact map palette, serve a custom style (MapTiler/Stadia raster or a
  MapLibre vector style from the spec's "Map palette" table). The OSM public
  tile server is fine for development only; use a tile provider in production.
- Sign in with Apple/Google, subscriptions, location and persistence are demo
  stubs. Platform folders (`ios/`, `android/`) are generated, not committed.
- Address search and "homes inside" use the bundled Sellwood extract; production
  needs a geocoding / address dataset behind `AddressRepository`.
- Prices and plan limits are placeholders pending business sign-off.
